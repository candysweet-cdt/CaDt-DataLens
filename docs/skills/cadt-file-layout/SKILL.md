# 文件目录规范（cadt-file-layout）

本技能约束 CaDt-DataLens 内置 AI 助手**在任意工作区里产生的文件**，随应用分发，对所有工作区生效。它不规定业务代码该放哪——那由项目自身的结构、`.gitignore` 和 `AGENTS.md` 决定。

## 1. 一句话原则

**用户要的正式文件按项目既有结构放；AI 自己产生的中间产物一律收进 `.cadt/`；应用全局状态只由应用自己写，AI 不碰。**

## 2. 三层分区

| 层 | 位置 | 归属 | AI 能做什么 |
| --- | --- | --- | --- |
| 工作区·用户态 | 工作区根下除 `.cadt/` 外的目录 | 用户与项目 | 仅在用户明确要求时写，沿用既有目录与命名习惯 |
| 工作区·助手态 | `<工作区根>/.cadt/` | 助手与用户共有 | AI 产物的默认落盘位置 |
| 应用态 | `%APPDATA%\CandySweet\CaDt-DataLens\` | 应用自己管理 | 只读，不写、不改、不删 |

`.cadt/` 通常已被项目 `.gitignore` 忽略（CaDt-DataLens 仓库即如此）。是否需要随团队共享由用户决定；确有需要时提示用户显式 `git add -f` 或调整忽略规则，**不要自行修改 `.gitignore`**。

## 3. 落盘决策树（核心）

1. **用户明确要一个交付文件**（报告、脚本、配置、数据、文档）→ 放到项目里同类文件所在目录。没有同类目录时先 `list_dir` 看结构再决定，仍不确定就 `ask_user`；**不要新建顶层目录**。脚本类另见第 6 节。
2. **用户要「做出来看看」的页面 / 图表 / 对比 / 方案** → 内容少就用对话内 `svg` / `html` 围栏卡片（`inline-visual`，不写文件）；内容多到需要留存、分享或打印 → `.cadt/answers/<slug>.html`（`answer-me-with-html`）。
3. **AI 自己产生的中间产物**（草稿、临时清单、导出快照、分析稿、一次性脚本）→ 收进 `.cadt/` 下对应的子目录；暂无对应子目录时放 `.cadt/` 根，并在回复里说明路径。**不要自造新的顶层目录**。
4. **跨文件改动且需审批 / 存档 / 撤销** → 用 `propose_patch`（`patch-workflow`），`.patch` 由应用写入 `.cadt/patches/`，不要手写补丁文件或自己造索引。
5. **长期记忆** → `.cadt/memory/`；**可复用工作流** → `.cadt/skills/<name>/SKILL.md`。这两类由专门功能管理，不要当草稿本用，也不要把一次性结论写进记忆。
6. **任何情况下都不要在工作区根目录散落** `report.md`、`output.html`、`temp.txt`、`temp.py`、`untitled-1.*` 这类文件；不要为了「先存一下」而写文件，能直接在回答里给就别落盘。

## 4. `.cadt/` 子目录职责

| 路径 | 用途 | 写入方 | 备注 |
| --- | --- | --- | --- |
| `memory/` | 持久记忆：`MEMORY.md` 索引 + 主题文件 | 记忆功能 | 长期保留，用户可手改 |
| `skills/` | 工作区技能（rank 100，可覆盖内置技能） | 技能管理 / 技能创建 | 一个目录一个 `SKILL.md`，附属脚本放技能内 `scripts/` |
| `answers/` | 单文件 HTML 回答页 | `answer-me-with-html` | 一次性产物 |
| `patches/` | `.patch`、`index.jsonl`、`manifest/`、`backup/` | 应用（补丁工具 / 补丁视图） | **系统托管，AI 只读** |
| `permissions.json` | 项目级权限规则 | 用户在权限页操作 | **AI 不得直接改** |
| `git-commit-style.json` | 提交风格 | Git 快捷操作首次询问后写 | 走一次写审批 |
| 根目录下的一次性脚本 | 必须落盘时的临时脚本 | AI（本轮） | 带 `tmp-` 与时间戳，**用完即删**；见第 6 节 |
| 新用途 | 先补进本表再使用 | — | 不要另起 `.cadt/` 之外的顶层目录 |

`.agents/skills/`（工作区通用，rank 200）、应用级 `ai-skills/`（400）、`~/.agents/skills/`（500）属于跨 agent 通用目录，不是本应用私有；往这些位置写之前先确认用户确实想让别的 agent 也用上。

## 5. 命名约定

- 小写连字符 slug；中英文与数字可保留，空白压成 `-`，剔除 Windows 非法字符 `\ / : * ? " < > |`、控制字符、结尾的 `.` 与空格；避开 `CON` / `PRN` / `AUX` / `NUL` / `COM1-9` / `LPT1-9`。
- 带时间戳的统一 `<yyyyMMdd>-<HHmmss>-<slug>`（本地时区），沿用 `patches/` 现有格式。slug ≤ 40 字符、整个文件名 ≤ 80 字符，防 Windows 长路径。
- 同名冲突追加 `-2`、`-3`，不用随机串；不要堆 `-final` / `-v2`。
- 扩展名与用途绑定：记忆与技能 `.md`、回答页 `.html`、补丁 `.patch`、配置 `.json`；脚本用项目同类脚本的扩展名，不要靠扩展名表达「临时」。
- 路径一律相对范围根，不写死绝对路径；`answers/<slug>.html` 同主题复用同名（覆盖前说明），不同主题另起 slug。

## 6. 脚本规范

脚本最容易在工作区根留下垃圾，按「**能不落盘就不落盘 → 落盘也要可识别、可清理**」处理。

### 6.1 三类脚本的落点

| 类型 | 落点 | 说明 |
| --- | --- | --- |
| 用户要的正式脚本（构建 / 部署 / 数据处理工具） | 项目既有的 `scripts/`、`tools/` 等同类目录 | 沿用项目的语言、命名与换行习惯；没有同类目录先 `list_dir`，不要新建顶层目录 |
| AI 一次性辅助脚本（探测、转换、校验、批量处理） | **优先不落盘**：用 `run_command` 的内联命令，或用应用「运行代码」的临时副本 | 确实需要文件时放 `.cadt/` 根，名字含 `tmp-` 与第 5 节时间戳，用完即删或在回复里说明保留位置 |
| 技能自带脚本 | 技能目录内 `scripts/` | 随技能一起分发；内置技能的 `scripts/` 只读，**不要往里写** |

不要在工作区根留下 `temp.py` / `check.ps1` / `fix.bat` / `test-1.*`；不要在版本库里留探测脚本。

### 6.2 编写约定

- 编码统一 UTF-8 无 BOM，脚本正文尽量纯 ASCII；含中文的 `.ps1` 例外——Windows PowerShell 5.1 按 ANSI 读无 BOM 脚本，需 UTF-8 BOM 或改用纯 ASCII 正文。换行沿用项目现有风格，`.bat` / `.ps1` 保持 CRLF，不要混用。
- 文件与参数路径不含空格、非 ASCII 字符；脚本内用相对路径或环境变量，不写死绝对路径、用户名、盘符；不内嵌密钥。
- 头部注释写清用途、参数、是否依赖额外包；一次性脚本再加一行「可删除」。
- 依赖不假设已安装：执行前用自检命令确认（应用「设置 → 编程语言」会扫描本机解释器）；技能脚本的依赖写进技能内 `requirements.txt` 并在 `SKILL.md` 说明，**不要静默 `pip install` / `npm install`**。

### 6.3 执行与清理

- `run_command` / `background_command` 用 `cwd` 指定工作目录，不要用 `cd` / `pwd` 探测；耗时脚本走 `background_command` 并用 `check_command` 轮询，不要阻塞对话。
- 内置技能脚本从技能根执行，或把 `scripts/...` 拼成绝对路径（用 `skill_use` 返回的「技能目录」）；不要先复制到工作区再跑，也不要改内置目录里的脚本。
- **不要用脚本绕过审批**：不把写文件、删除、批量重命名塞进脚本里代替 `write_file`，不把危险命令拆成脚本片段规避逐条审批；只读档与计划模式不执行脚本。
- `.cadt/answers/*.html` 是给用户看的单文件页面：不要依赖外链 CDN、远程字体或联网资源；对话内 `svg` / `html` 卡片会清洗脚本，别把关键内容只放在脚本里。
- 一次性脚本用完删除（或向用户确认保留）；删除前先确认是自己本轮创建的文件，不碰用户已有文件。

## 7. 硬禁区（只读，任何权限档都不写）

- `.git/` 及版本库内部文件；符号链接 / junction 指向工作区外的目标；越界路径（`..`、盘符、UNC）。
- `.cadt/patches/`（含 `backup/`、`manifest/`、`index.jsonl`）、`.cadt/permissions.json`、`.cadt-builtin-version`。
- 应用数据目录里的 `ai-config.json`、`ai-sessions/`、`ai-index.db`、`ai-schedule.db`、`builtin-skills/`、`activity/`、`logs/`、`config.json`、`WebView2/`。
- 项目自身的生成物目录（以 `.gitignore` 与构建脚本为准，例如 `dist/`、`bin/`、`node_modules/`、自动生成的绑定目录）：由构建工具写，AI 不改。
- 用户未要求的删除、批量重命名、批量移动：不做；要清理就先列清单让用户确认。

前两类会被写工具与补丁应用直接拒绝；应用数据里既有会话正文等**真源**，也有系统托管状态，改了会破坏会话、审批记录与搜索索引。内置技能目录 `builtin-skills/` 版本更新时会被覆盖，定制请复制到工作区或应用级技能目录后再改。

## 8. 可删除 / 可重建

| 可安全删 | 后果 |
| --- | --- |
| `.cadt/answers/*.html` | 只是一次性回答页，重新生成即可 |
| `.cadt/` 根下本轮创建的一次性脚本 | 用完即删，不留残骸 |
| `ai-index.db`、`ai-schedule.db` | **派生索引**，删除后首次使用自动重建；会话 JSONL 与触发指令原文才是真源 |
| `.cadt/patches/` 下已确认不需要的旧补丁 | 删除前确认不再需要撤销，且通过索引管理 |

| 不可删 | 原因 |
| --- | --- |
| `ai-sessions/` | 会话真源（追加式 JSONL，含图片外置） |
| `.cadt/memory/` | 用户长期记忆 |
| `.cadt/patches/backup/` | 撤销补丁的唯一依据 |
| `ai-config.json` | 模型账号、偏好、审批白名单 |

清理前先 `list_dir` 列出真实文件，只处理用户明确确认过的路径，一次不要动太多。

## 9. 权限与降级

- `.cadt/` 与 `AGENTS.md` 是**风险路径**：自动审批档下仍会退回逐次审批。不要试图绕过——不把一次写入拆成多条普通写，也不用 `run_command` 代替写工具落盘。
- 只读档与计划模式：只能读和写记忆；需要落盘时，在计划里写清目标路径，批准后再执行。
- 没有工作区（只打开单个文件）时：补丁等由应用自动回退到应用数据目录；其余产物先问用户要放哪，不要在工作区之外乱写。
- 工作区 `AGENTS.md` 与本技能冲突时以 `AGENTS.md` 为准（项目规则优先），但**第 7 节硬禁区不因此放宽**。

## 10. 与其他技能的关系

| 技能 / 功能 | 落盘位置 |
| --- | --- |
| `inline-visual` | 不写文件，对话内卡片 |
| `answer-me-with-html` | `.cadt/answers/<slug>.html` |
| `patch-workflow` | 应用托管的 `.cadt/patches/` |
| 技能创建 | `.cadt/skills/` 或应用级 `ai-skills/` |
| 记忆（workspace 模式 / app 模式） | `.cadt/memory/` / 应用数据 `ai-memory/` |
| 运行代码 / `run_command` | 优先不落盘；一次性脚本见第 6 节 |

## 11. 完整路径表

`reference/paths.md` 逐条列出每个路径的写入方、真源或派生、生命周期、是否入 git、能否手改。用 `skill_use` 返回的「技能目录」拼上该相对路径，通过 `read_file` 读取。
