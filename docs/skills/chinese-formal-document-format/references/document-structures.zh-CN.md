# 文种结构参考

这里描述常见结构，不强制改写用户原文。用户草稿结构不同，就按现有内容排版。

## 报告

用途：向上级汇报工作、说明情况或答复询问，不用于请求批准。

常见结构：

1. 标题：`关于××工作的报告`；
2. 主送机关（可选）；
3. 引言：`现将……报告如下。`；
4. 正文：完成情况、存在问题、下一步安排；
5. 结束语：`特此报告。`（可选）；
6. 落款、日期。

注意：

- 报告夹带“请批示”等内容时，只提醒，不删除；
- 保留原文中的编号和数字。

## 方案

用途：部署未来工作的实施方案、工作方案、项目计划。

常见结构：

1. 标题；
2. 背景和目标；
3. 总体要求；
4. 主要任务；
5. 实施步骤和时间安排；
6. 保障措施；
7. 落款、日期（部分内部方案可省略）。

时间、责任部门、任务表格都按原文保留。

## 函件

用途：不相隶属或平级单位之间商洽、询问、答复事项。

常见结构：

1. `关于××的函`；
2. 主送机关；
3. 来函背景或前期沟通；
4. 具体事项；
5. 商洽式结束语；
6. 联系人（可选）；
7. 落款、日期。

函件应保持平等商洽语气。发现语气不当只提醒，不擅自改写。

## 会议纪要

常见结构：

1. 标题；
2. 元数据：会议时间、地点、主持人、出席、列席、缺席、记录人；
3. 议题；
4. 议定事项；
5. 落款（可选）；
6. 发文日期。

元数据块：

- 仿宋 16 pt；
- 左对齐；
- 不设首行缩进；
- 每项独立成行。

议定事项：

- `一、`、`二、`等独立结构标题按一级标题；
- `1. 责任分工` 这类短标签可按三级标题；
- `1. 由市场部牵头，于10月25日前完成任务。` 是正文，不是标题；
- 不自动添加“特此报告”等结束语。

## 其他常见材料

通知、请示、批复、意见、决定、通报、简报和一般内部材料可以共用排版引擎，但本 Skill 不强行规定其完整文体结构。

处理原则：

1. 第一个非空段落通常作为标题；
2. 保留主送、正文、附件、落款、日期原顺序；
3. 按原文已有的编号设置层级；
4. 无法判断文种时使用 `generic`；
5. 只提醒内容问题，不擅自改写。

### 通知

常见要素：标题、主送、事项、行动要求或时限、落款、日期。

### 请示

常见要素：标题、一个主送机关、一个事项、请求语、落款、日期。多个无关事项时只提醒“一文一事”问题。

### 批复

常见要素：标题、主送、对原请示的回应、决定、日期。保留原引用的文号和决定措辞。

### 讲话、简报、研究材料

只有用户明确要求正式材料版式时，才套用本文的标题、层级、正文和落款规则；不要自动把它们当作正式外发公文。
