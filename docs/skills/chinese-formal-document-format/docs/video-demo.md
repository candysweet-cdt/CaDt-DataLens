# 中文正式文档排版：视频演示建议

建议用 45～60 秒完成一次可验证的演示，不把重点放在讲参数。

## 镜头 1：先制造一个真实痛点（8 秒）

打开排版前样稿，快速指出：

- 标题、正文和表格字体混杂；
- 行距和缩进不统一；
- 手动全选改字体容易顺带改坏结构。

口播示例：

> 这份材料内容都写好了，真正麻烦的是每一级标题、表格和落款都要重新调。更怕的是 AI 一顺手，把原来的字也改了。

## 镜头 2：一句话触发（7 秒）

在 Agent 中输入：

> 按中文正式文档格式排版，不要改任何文字。输出 DOCX 和格式核验报告。

口播示例：

> 我对它只说一件事：只改格式，不改一个字的正文。

## 镜头 3：展示结果与核验（20 秒）

可直接用 `examples/previews/before/02-minutes/page-1.png` 和 `examples/previews/after/02-minutes/page-1.png` 做前后对比录屏，避免现场等待渲染。

也可以直接用 `docs/chinese-formal-document-before-after.png` 作为画中画或转场底板。

打开排版后 DOCX，展示：

- 标题、正文、各级标题字体；
- 固定行距和段落缩进；
- 表格表头与内容；
- 落款和日期位置。

讲到这里可以补一句：编号不等于标题。`1. 完成情况` 是短标题；`1. 由市场部牵头，于10月25日前完成任务。` 是正文，系统会按句子形态区分。

再打开 `verify-report.json`，只展示三项：

1. 正文与关键结构一致；
2. 页面与页边距通过；
3. 字体、字号、行距、缩进通过。

口播示例：

> 它不是排完就说“完成了”。原件和成品的正文、表格、页眉页脚会逐项对比，少一个字、少一个单元格都会停止输出。

## 镜头 4：说明通用性（12 秒）

展示配置文件变化：

> 默认是参考版，单位有自己的字体和页边距，就换一个组织配置。规则在配置里，不用为了每家公司改一遍提示词。

口播示例：

> 所以它不是一个单位的专用模板。默认规则是一套，单位差异用配置覆盖，Codex、Claude Code、Word 加载项和普通 Python 环境都能走同一套核验。

## 镜头 5：给边界（8 秒）

口播示例：

> 它适合已经写好、只想规范版式的报告、方案、函和会议纪要。内容润色、红头版式、正式发文合规审查不包。正式发出前，还是要在安装了本单位字体的 Word 或 WPS 里看一遍分页。

## 视频封面文案

主标题：

> 只改排版，不改一个字

副标题：

> 一个可核验的中文正式文档排版 Skill

## 发布包应提供

- Skill 安装包；
- `examples/before` 和 `examples/after` 各三份样稿；
- 至少一份完整核验报告；
- 安装说明；
- 默认配置与一个组织覆盖示例；
- 字体和正式发文边界说明。
