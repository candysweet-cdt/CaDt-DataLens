## 一句话介绍

这份使用手册与配套 Skill 分享包由「鼓翼成长星球」出品并持续维护。品牌只用于说明与分享材料；排版用户文档时仍严格保持正文、数字、标点、表格和页眉页脚不变。

这是一套面向中文 DOCX 的正式文档排版工具：参照 GB/T 9704-2012 的常见版式，整理标题、正文、分级标题、落款、日期、页面和表格，同时核验正文内容是否被改动。

核心承诺只有一句：

> 只改格式，不改一个字。

它适合报告、方案、函件、通知、请示、会议纪要、工作总结等正式材料，也允许按不同单位的字体、页边距和行距建立独立配置。

## 先看边界

### 适合处理

- 有明确标题和正文层级的 DOCX；
- 已分好 `一、`、`（一）`、`1.`、`（1）` 层级的文稿；
- 需要统一页面、字体、字号、行距、缩进和表格样式的材料；
- 需要保留原文，并额外获得格式核验结果的文档。

### 不适合处理

- 替用户改写、润色、扩写、缩写或翻译正文；
- 自动补红头、文号、印章、版记、页码、附件页或落款；
- 直接排版 `.doc`、扫描 PDF、图片或不可编辑的 PDF；
- 未经核验就声称满足某个单位的正式发文规定。

默认样式是参考版式，不等于“法定合规认证”。正式发文仍应以本单位现行模板和审批制度为准。

## 压缩包里有什么

```
chinese-formal-document-format/
├── SKILL.md                 # Agent 的执行说明
├── README.md                # 完整项目说明
├── profiles/
│   ├── default.json         # 默认版式参数
│   └── example-org.json     # 单位自定义样式示例
├── scripts/
│   ├── format_docx.py       # 排版主程序
│   ├── verify_docx.py       # 排版结果核验
│   └── render_preview.py    # 字体感知的预览生成
├── templates/               # 报告、方案、函、会议纪要模板
├── examples/                # 匿名示例和前后对比
└── tests/                   # 自动测试
```

字体文件不包含在压缩包内。DOCX 只记录字体名称，目标电脑需要安装相应字体。

## 最快安装方式

### 方式一：安装到 Codex

1. 解压分享包；
2. 得到完整文件夹 `chinese-formal-document-format`；
3. 将整个文件夹放到 Codex 的 Skills 目录：

macOS / Linux：

```bash
~/.codex/skills/chinese-formal-document-format/
```

Windows：

```text
%USERPROFILE%\.codex\skills\chinese-formal-document-format\
```

4. 重新打开 Codex 或刷新可用技能；
5. 上传一份中文 DOCX，对 Agent 说：

> 使用“中文正式文档排版”技能，按默认正式文档格式排版。只改格式，不改正文、数字、标点和表格内容。输出格式化后的 DOCX 和核验报告。

### 方式二：上传到支持 Skill 的聊天产品

如果所用产品支持上传 Skill 包，可直接上传 `.zip` 或 `.skill` 文件，然后按“方式一”的提示语使用。

如果平台只能对话、不能稳定生成和核验 DOCX，建议改用本手册的“方式三”，不要在聊天里接受一份无法下载的近似结果。

### 方式三：在本地运行 Python 脚本

需要 Python 3.10 或更高版本，以及 `python-docx` 1.1.2 或更高版本。

先进入解压后的 Skill 根目录：

```bash
cd /path/to/chinese-formal-document-format
```

首次安装依赖：

```bash
python3 -m pip install -r requirements.txt
```

开始排版：

```bash
python3 scripts/format_docx.py 输入.docx 输出.docx --strict
```

核验结果：

```bash
python3 scripts/verify_docx.py 输出.docx --reference 输入.docx
```

需要逐页预览时：

```bash
python3 scripts/render_preview.py 输出.docx preview/
```

建议始终加上 `--strict`。它遇到修订痕迹、内容控件或文本框时会停止，避免出现“看起来排好了、实际有内容漏改”的情况。

## 日常使用方法

### 第一步：准备文件

使用可编辑的 `.docx`。建议先保留原始文件，再让 Skill 输出到新文件，例如：

```text
输入：季度经营分析-原稿.docx
输出：季度经营分析-正式版.docx
```

### 第二步：明确文种

可以直接告诉 Agent 文档类型：

```text
按“季度报告”排版
按“实施方案”排版
按“会议纪要”排版
按“函件”排版
```

如果文种不清楚，Skill 会要求确认。不要让它靠猜改变文档结构。

### 第三步：给出明确要求

推荐提示语：

> 使用“中文正式文档排版”Skill 处理附件。文种按报告处理，采用默认参考版式。先保留原文件，再输出一份新 DOCX 和 `.format-report.json`。不得改动任何文字、数字、标点、段落顺序、表格和页眉页脚。完成后运行内容完整性与版式核验，并告诉我核验结果、需要人工确认的地方和字体风险。

### 第四步：检查交付物

正常情况下会得到：

1. 格式化后的 `输出.docx`；
2. `输出.docx.format-report.json`；
3. 核验后的 `输出.docx.verify-report.json`；
4. 可选的 PDF / PNG 预览。

报告中最重要的两个字段应是：

```text
content_integrity.passed = true
status = passed
```

只要内容完整性检查失败，就不要使用输出文件。

## 默认版式

| 元素 | 字体 | 字号 |
|---|---|---|
| 标题 | 方正小标宋简体 | 二号，22 pt |
| 正文 | 仿宋_GB2312 | 三号，16 pt |
| 一级标题 `一、` | 黑体 | 三号 |
| 二级标题 `（一）` | 楷体_GB2312 | 三号 |
| 三级标题 `1.` 或 `1、` | 仿宋_GB2312 加粗 | 三号 |
| 四级标题 `（1）` | 仿宋_GB2312 | 三号 |
| 表格 | 表头黑体、内容仿宋_GB2312 | 四号，14 pt |

页面为 A4，页边距上 37 mm、下 35 mm、左 28 mm、右 26 mm；正文固定行距 28 pt，首行缩进 2 字符。

可执行参数以 `profiles/default.json` 为准。

## 单位有自己的模板怎么办

不要直接改默认配置。复制 `profiles/example-org.json`，按单位名称另存一份，只覆盖不同的项目。例如：

```bash
python3 scripts/format_docx.py 输入.docx 输出.docx \
  --profile profiles/某某集团.json \
  --strict
```

核验时使用同一个 profile：

```bash
python3 scripts/verify_docx.py 输出.docx \
  --reference 输入.docx \
  --profile profiles/某某集团.json
```

建议在 profile 中记录单位名称、审批人和生效日期。排版与核验必须使用同一套参数。

## 常见问题

### 1. 为什么编号 `1.` 有时是标题，有时是正文？

看它是不是一个完整的句子。

- “1. 完成情况”更像短标题，可以按三级标题处理；
- “1. 由市场部牵头，于10月25日前完成任务。”是完整正文，不得加粗成标题。

Skill 会依据内容判断，也会在层级仍不清楚时询问。

### 2. 会不会悄悄改掉我的文字？

排版前后会核对正文段落、段落顺序、表格行列和合并关系、单元格文字、页眉页脚。任何一项不一致都会停止保存。

它不会自动修正错误内容。日期格式、报告夹带请示语、数字前后不一致、缺失落款等问题只会提示。

### 3. 为什么打开后字体和预览不一样？

DOCX 不包含字体文件。接收方电脑需要安装对应字体。不要在预览器缺字体时擅自替换 DOCX 中的字体名称，否则正式文件会发生变化。

### 4. 为什么 PDF 和扫描件排不了？

本 Skill 直接处理可编辑 DOCX。PDF 或扫描件需要先转换为 DOCX，并核对转换后的文字没有缺失，再开始排版。

### 5. 有修订痕迹、文本框或内容控件怎么办？

使用 `--strict` 时脚本会停止并提示风险。先接受或清理修订，必要时压平内容控件，再重新运行。

### 6. 它能不能自动加红头、文号和印章？

不能。默认只处理已有正文的排版，不生成法定公文要素，也不替代单位审批。

### 7. 合并单元格会不会被破坏？

脚本会检查表格结构。复杂合并表格出现异常时必须停止，不能带着损坏的结构交付。

## 分享与安全建议

- 分享前无需提供个人真实材料；示例目录已经包含匿名示例；
- 发给朋友时，同时提供本手册和压缩包；
- 不要把单位的真实模板、未脱敏正文或字体文件公开发布；
- 字体如属商业授权，只记录名称，不要随包分发；
- 对外发送文档前，另行检查作者信息、修订记录和隐藏元数据。
