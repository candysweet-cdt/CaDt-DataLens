# 数据安全与权限

> 本文档从 [README.md](../../README.md) 外迁并归类，收录散落在各功能章节里的安全机制。
> 项目总览与快速上手见 README。

CaDt-DataLens 的安全设计围绕三条主线：**数据不出本机**、**危险操作必经过用户**、**AI 的一切写入可审阅可回滚**。

## 一、数据本地化

- 所有文件读写都在本机完成，不上传文件；配置、会话、记忆、定时任务全部本地持久化，统一存放在 `%APPDATA%\CandySweet\CaDt-DataLens\`（详见 [数据查看与开发](data-viewing.md) 的「外观」末条）。
- 应用数据目录（含 API 密钥与会话数据）对 AI 任何权限档都拒绝读取。
- 密码经 Windows DPAPI 加密单独落 `db-credentials.json`（复合键防撞；换用户 / 换机器解不开时提示重存，绝不覆盖）。详见 [一键运行与数据库](run-and-database.md)。
- 涉密值（API Key、令牌等）建议经应用的环境变量登记功能录入，值由用户在弹窗里亲自填写，不进对话、不落明文。
- MCP 子进程的环境变量自动过滤疑似密钥变量；服务提供商的 Key 只存本机 0600、界面不回显明文。

## 二、权限四档与审批链

- 四档：**只读访问 / 每次询问 / 自动审批 / 完全权限**。可为每次新建会话设默认档位（默认「每次询问」），历史会话保持各自档位。
- 自动审批直接放行只读命令与已知命令族、自动应用工作区写入（风险路径除外）；危险命令只确认一次。完全权限启用前有风险说明确认。
- 项目级规则 `.cadt/permissions.json` 支持 `Bash(...)` / `Write(...)` / `Web(...)` / `Read(...)` 的 allow / ask / deny；设置页提供规则表格增删、审批记录一键成规则、会话授权单条管理。项目 `Bash(...)` 规则优先级最高，可压过完全权限。
- 命令 / 写入完成后卡片标注放行来源（只读命令 / 命令族 / AI 分类器 / 本会话 / 项目规则 / 完全权限 / 用户已批准），来源与用户裁定随会话持久化。
- 工作区外读取按档分流：用户明确给过路径的直接读；未点名的越界读取在自动 / 完全档直接读，只读 / 每次询问档弹审批卡（可勾选记住目录）；子代理继承主代理已批准的目录。
- **动作审批面板**：修改中高风险设置、安装卸载插件等高危 `app_control` 动作统一弹审批卡，写清动作、目标、原值 → 新值、发起会话、来源与危险度；一次性授权、不记住，批准与拒绝都进操作记录。布局形态类设置永久不可由 AI 写。
- 插件与应用同权限运行（可读写本机文件、执行命令），从仓库或市场安装前弹确认框提示风险；卸载是永久删除，除完全权限外恒审批。
- 可选的**端侧自动分类器**（linear / ONNX）判定规则未覆盖的命令，默认关闭；分类请求走串行队列、重复合并、结果缓存 10 分钟，用户点停止会撤销在飞与排队请求转人工确认。

## 三、补丁（.patch）—— 改动可审阅可回滚

- AI 可用 `propose_patch` 把改动写成标准 unified diff（存 `<工作区>/.cadt/patches/`），审批卡里逐文件列出可应用 / 冲突、勾选要应用的项、选择「整体成功」或「允许部分成功」（AI 侧默认后者），点「应用」才落盘。
- 应用是两阶段：先全量预检（不写盘），再按模式提交；每个文件写前都会把原始字节备份到 `.cadt/patches/backup/`，可一键撤销。
- 失败与跳过都会给出「期望 vs 实际」的具体原因和建议，并以 `【patch:error】` / `【patch:result】` 回给模型自修（同一补丁最多 3 次）。
- 打开任意 `.patch` 也能在补丁视图里直接应用，不依赖 AI；命令行 `--check-patch` / `--apply-patch --yes` / `--revert-patch` 同样可用。
- 补丁视图的「目标」目录可直接点选更改；路径普遍落空时会就近探测并建议更可能的目录，补丁文件与目标工程不必在同一工作区。

## 四、隔离工作区（git worktree）—— 高风险改动关进沙盒

- 有风险的批量改动 / 大规模重构交给 AI 在独立 worktree 里试：改动落在 `<主根>/.cadt/worktree/<slug>/`（新分支 `cadt/wt/<slug>`），主根全程零改动。
- 完成后经 `worktree_manage(action=export)` 导出补丁，走与补丁同一条审批卡回灌主根，**回灌卡全档必弹（含完全权限档）**，永远人工审阅。
- 隔离期间主根只读：`write_file` / `edit_file` 写主根会被确定性拒绝；隔离会话里 `propose_patch` 全档必弹审批卡，补丁回灌是唯一写主根通道。
- 子代理也能有隔离区（`spawn_agent` 的 `isolation: 'worktree'`）：写效应圈定在自己的前缀内，主代理 `export` 审阅回灌。
- 依赖目录只共享主根顶层的 `node_modules` / `.venv` / `venv`；`.worktreeinclude` 可把被忽略的 `.env` 等文件拷进隔离区。
- 创建 / 丢弃隔离区会写进会话历史；丢弃前检查终端占用；可清理没有会话登记的孤儿隔离区。

## 五、子代理命令沙箱（Windows 受限令牌 + ACL）

- 子代理可执行命令：`run_command`（一次性）、`background_command` / `check_command` / `stop_command`（长任务）。
- **文件写入由系统层圈定**：受限令牌（`WRITE_RESTRICTED` + Low 完整性）下，写效应只允许落在本次任务的工作区根（有隔离 worktree 时即草稿目录）与一次性私有临时目录内，其余写入被拒绝；读、网络不受这层限制，完整度如实标 `partial`。
- 档位随父会话：只读 / 每次询问 → 一个写根都不给；自动审批 → 工作区可写；完全权限 → 不圈定。子代理永不弹审批卡（后台无人可问），但项目写死的 deny 规则照旧生效。
- **沙箱建不起来就拒绝执行**（fail-closed，不降级裸跑）；沙箱里的 shell 是 PowerShell（Git Bash 的 Cygwin 运行时在受限令牌下起不来）。
- 授权会在工作区留下能力 SID 的 ACE、Everyone 的「禁止删除子项」deny 与 Low 完整性标签，可在 设置 → 权限 →「子代理命令沙箱」检查与清除，只删本应用写入的条目。
- **定位**：这是误操作兜底，不是隔离保证——硬链接别名可绕过能力 SID，读与网络完全不受限；写根必须是 NTFS 目录；首次授权要遍历整棵工作区树，大目录会有等待。详见 [子代理沙箱设计](../finished-plans/subagent-sandbox.md) 与 [事故复盘](../reports/incident-2026-11-27-sandbox-low-label.md)。

## 六、文件与外部数据的保守处理

- 只读锁：状态栏右下角一键把当前及之后所有文件设为只读，阻止树编辑、代码 / 文本输入、表格编辑、保存与格式化。大文件（>10 MB）与二进制文件自动只读，>100 MB 拒绝打开。
- Markdown 预览原始 HTML 不执行，外部链接交给系统浏览器；HTML 预览用 iframe sandbox 隔离。
- SQL 查询只作用于临时 SQLite 副本，`ATTACH` / `DETACH` / `VACUUM` 被拒；数据库默认只读是双保险（SQLite `mode=ro`、MySQL `SET SESSION TRANSACTION READ ONLY` + 连接池限 1），写操作需连接级「允许编辑」显式授权 + 全局只读锁放行，危险语句与缺 WHERE 的 UPDATE/DELETE 走两阶段确认。详见 [一键运行与数据库](run-and-database.md)。
- 外部修改保护：文件被其他程序修改时，未编辑标签自动重载；已编辑标签不被静默覆盖，保存时弹冲突对话框。
- 操作记录：打开 / 保存 / 删除 / 重命名 / 格式化、设置变更、AI 审批与工具执行摘要按月存入本机 `activity/*.jsonl`，只记操作摘要，不记录文件正文与密钥。
- 存储与清理：逐条显示本应用自己产生的缓存与数据占用，清除数据按勾选处理、送回收站，「不可恢复」条目在确认框逐个点名；支持按时间 / 大小阈值自动清理，范围不含网页登录态与用户数据。
